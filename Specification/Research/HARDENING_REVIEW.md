# Hardening review and fix plan

Reviewed branch `fix/v1-vm-hardening` at `6777bd555ae2fc062b9609c2943e70d9ad1dd49e`. Two reviewers received the same task, separate checkouts at that revision and separate Arch VirtualBox guests. The checks below distinguish behavior reproduced on the baseline from candidate changes measured in disposable builds.

## Implementation and verification

- The keyboard, close shortcut, focus query and event subscription now agree while a new tile waits for a replacement buffer. Workspace reselection preserves the pending layout. Two-output headless tests covered both buffer arrival orders and destruction during the wait. The Arch TTY trials exercised Dwindle, scrolling, workspace reselection, resize reversal and focus before and after presentation.
- The live config reader follows profile links and handles pathname truncation, hard-link publication and lost close notifications. The guest trial overflowed the actual 16,384-event inotify queue twice, checked that an open prefix stayed out of last-good state, and observed the completed save. It also recovered a profile that temporarily pointed to a directory. The user guide covers filesystems and ownership arrangements that restrict read leases. [Configuration guide](../USER_GUIDE.md)
- A rejected idle power transition rearms after fresh input. Night light retries a rejected update on a synchronized composed frame. Twelve deterministic display scenarios covered enable, temperature change and disable under transient and persistent rejection. The guest exercised real sleep, wake, cursor restoration, gamma changes and captures. Over one 6.16-second idle sample the kernel reported zero additional compositor CPU ticks and its main thread made 52 voluntary context switches. The observation timer still checks for faults and deadlines.
- Optimized DRM builds now pass GCC's warnings-as-errors checks. The default build compiles the cursor path at both `-O2` and `-O3`. Trace export created private directories and files under umasks `000`, `002` and `022`. VM diagnostics covered empty, running and stopped traces.
- Floating resize projects the affected window and its dialogs. Window queries use a live ID index and construct each result row once. An unchanged IPC publication with a long connector name went from one measured C++ allocation to zero. An ordinary short connector already required zero. The projection and query report gives complete operation timings, including the small-desktop tradeoff. [Performance measurements](HARDENING_PERFORMANCE.md)
- The portal test waits for an actual sampled buffer before submitting each single-update color assertion. The installed-package workload records DMA-buffer counts by exporter and byte size across repeated mode changes, then checks descriptor and memory cleanup over 48 workspace cycles and 45 seconds of fullscreen presentation at the restored mode.
- The guest captured a monitor, native window and X11 window, recorded a playable H.264 stream, retained keyboard focus across a VT switch and survived portal service restarts. A disposable Arch guest started with its only virtual connector disabled and restored the client, focus and cursor after the kernel hotplug event. Physical display latency, native AMD VRR and system suspend/resume require separate hardware qualification.

## Recommended order

- Fix the optimized build first so all performance work and regression tests can run with release-like flags.
- Fix keyboard focus, no-op workspace selection and overlapping openings on two outputs. All three are observable before an existing client submits its replacement buffer.
- Restore config reloads when a profile link changes and rearm the display-sleep timer after a driver rejection. Each has an independent regression fixture.
- Address first-time trace export and transient night-light commit failure. Exercise both success and rejection paths.
- Reduce repeated scene work after measuring full resize and query costs. Keep the ordered window-ID and diagnostics cleanups small enough to validate independently.

## Build and correctness

### GCC fails to build the optimized cursor path

With Arch GCC 16.2.1, clean Meson `release` and `debugoptimized` builds fail on `move_cursor` at [tty_drm.c](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/tty_drm.c#L1064). GCC reports both output coordinates as possibly uninitialized, and the project treats warnings as errors. In `nearest_output`, selecting an output sets both coordinates. The caller returns on a null target. The confirmed failure is compilation. The control flow supplies both coordinates whenever the caller uses them.

Initialize the coordinates from the requested position before calling `nearest_output`. A disposable checkout with just that change built all targets with `--buildtype=debugoptimized`. The host unit and integration suites then passed 43 checks with three portal checks skipped. Add an optimized build to the verification commands, leave warnings enabled, and exercise cursor movement between outputs and behavior with no usable output. Record the package build separately, since Arch packaging supplies its own build flags.

### A close shortcut can reach the wrong window while a tile opens

When a new tile maps, its neighbor can take up to the 90 ms opening deadline to supply a resized buffer. The window manager selects the new tile immediately. The Wayland seat still routes keys to the visible client until projection. `Desktop::dispatch` and `SessionControl::focus_state` read the window manager's selection, so an untargeted close and an ordinary key can go to different clients. See [desktop.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L449) in `window_event`, `update_keyboard_focus` and `dispatch`, and [session_control.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/session_control.cpp#L195) in `focus_state`.

A disposable extension of `run_pending_opening_focus` sent a key and an untargeted close in that interval. Client 3 received the key. Client 4 received the close while still waiting to appear. The stock test covers a click during opening. The failure occurs before a click.

Make the desktop expose the toplevel that currently receives keyboard input. Resolve an omitted window ID and serialize focus queries and focus events from that value. Update it when the seat focus is projected, including a click during a pending opening. Preserve explicit-ID targeting and null focus for a layer surface. Add a real-client test for key delivery, close targeting, query and event consistency before completion, after a visible-window click, after normal completion or timeout, and on target destruction.

### Re-selecting the current workspace can publish an unfinished layout

While a new tile and its neighbor are waiting on their replacement buffers, press the shortcut for the current workspace or make the corresponding IPC request. `dispatch` recognizes the no-op, then still calls `project`, which clears the opening transaction and its deadline. In a headless two-client fixture, the request returned `changed=false` while the pointer target at (110,45) changed from window 1 to window 2 before the original client supplied its resize buffer. The existing fixture expects the old contents and hit target to remain together during this interval. See [desktop.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L643) in `dispatch` and `project`.

Return early for a genuine workspace no-op. Check other dispatch paths that report no change for real side effects, including completing a focus cycle, canceling a drag and raising a window. Test that a no-op preserves pixels, hit target and the original deadline. A disposable early return preserved the old pixels and hit target in the same fixture, which then passed through buffer delivery. Also test that an actual workspace switch can still supersede the pending opening.

### Overlapping openings on two outputs can release the first layout early

The opening tracker holds a single map. Each call to `stage_opening` collects the newest window's workspace and replaces the map. A second output can therefore release the first output's layout when only the second workspace has caught up. A two-output headless test held back the first workspace's resized buffer, opened a tile on the other output, and supplied only that output's buffer. The first output's hit target changed from window 3 to window 4 in 5 ms, well within the 90 ms deadline. See [desktop.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L359) in `stage_opening` and `opening_ready`.

Preserve pending windows in other workspaces when recalculating one workspace. A narrow first fix can retain the existing shared deadline and require all surviving participants to settle before a full projection. Test both completion orders, a disappearing output or client, and the timeout. Consider independent per-output presentation only if the shared deadline is measurably disruptive.

### Reloading a config selected through a chain of symlinks

Changing a dotfile profile can leave the running compositor on the old profile until another watched path changes or the user restarts it. The watcher resolves the entire final-component chain and installs directory watches only for the configured name and the final target. An atomic rename of an intermediate link in a third directory reaches neither watch. See [live_config.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/live_config.cpp#L94) in `symlink_target` and `refresh_watches`.

A disposable extension to `LiveConfigTest` created `config.toml → profiles/active → files/work`. After startup settled at `gaps_outer=21`, the test renamed a fresh link to `profiles/active` so it pointed to `files/home`. The filesystem resolved to the new target. The active value remained 21 throughout a three-second dispatch window instead of changing to 34. A subsequent save of 35 to the new target also went unobserved. The existing direct-link replacement test passed in the same binary.

Retain a bounded list of the link names encountered while resolving the chain. Watch their parent directories, deduplicate kernel descriptors and rebuild the watch set when a relevant link is replaced. Keep the existing generation check and completed-write rules. Extend the live-config suite with the profile switch, a subsequent edit, and invalid-candidate recovery. Assert the persisted snapshot follows only accepted changes.

### Restart the idle deadline after the driver rejects sleep twice

A display can stay awake indefinitely after two rejected power-off commits. When the display is still awake and no other output has a pending deadline, `IdlePower::update` disarms the timer after its bounded retry. The next pointer or keyboard event clears the failed sleep request and records activity, but does not schedule another check. An unrelated window or policy change can make the problem disappear. See [idle_power.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/idle_power.cpp#L96) in `activity` and `update`.

A disposable `IdleTrial` rejected the initial sleep and its retry, delivered local input, advanced the policy clock another 15 minutes, and dispatched the Wayland loop. Two attempts had been made. Calling `visibility_changed` then triggered the third. The test uses a real event loop with a simulated clock and power callback.

When fresh input clears an exhausted sleep retry for an awake output, schedule a policy recheck so the next timeout can be armed. Keep ordinary mouse motion cheap and retain the driver retry limit. Add the failing sequence to the idle suite without using the fixture helper that injects a visibility change on each clock advance. A disposable change that rearmed this case passed all eight idle tests, including the new regression. Also check that a second output's deadlines and inhibitors remain independent.

### Config reload can wait indefinitely for a missing close notification

Two operations produced a valid file on disk that Seaside never applied during a 600 ms observation window. A pathname-based `truncate(2)` removed a whole setting, but its previous value stayed active. Publishing a completed staging file with `link` and immediately unlinking the staging name left `gaps_outer` at 25 instead of 42. An ordinary atomic rename succeeded in the same run. In the first case the watcher sees a modification without a write-close. In the second, the new config already has a link count of one when the event loop calls `lstat`, so the watcher treats it as a newly opened file. In both cases it disarms the timer while waiting for a notification that the completed operation will never generate. See [live_config.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/live_config.cpp#L176) in `record_write`, `created_regular_file` and `arm_reload`.

A third fixture injected an inotify overflow notice in place of a dropped close after a delivered modification. The writer had closed, but the new value still failed to apply. The overflow path refreshes watches while retaining the incomplete write state. Add these three sequences beside the existing tests that hold a writer open on a valid TOML prefix. Trace open, modify, close and directory-entry events for each sequence. Prototype a bounded way to recognize completion on filesystems the project supports. Gate any change on both completed saves applying and the open prefix staying unpublished for the lifetime of the writer, including across an overflow. A timer or a stable file size alone cannot distinguish a paused writer. Until the regression set can satisfy both guarantees, atomic rename or a normal open/write/close is the working save method.

### Trace export can create a state directory it then rejects

A first trace export with a missing Seaside state directory inherits the process umask through `create_directories`. With a group-writable result, the following ownership and mode check correctly refuses it. Four of six trace tests failed with each of umask 000 and 002. All six passed with 022. Existing private state directories, including those normally created for a recovery snapshot, bypass this creation path. See [trace.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/trace.cpp#L93) in `write_trace` and [trace_test.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/tests/unit/trace_test.cpp#L68).

Create the new Seaside state directory with a private mode at creation time, verify the opened directory, and retain the current rejection of an existing unsafe directory. Cover missing versus existing directories under 000, 002 and 022, including a first export before a recovery snapshot exists. Test the real export response and verify the file and directory modes.

### A transient commit failure can leave night light on after it is switched off

`prepare_night_light` clears the pending flag before committing the display state. If that commit fails, the follow-up frame omits the color lookup table (LUT). In a headless test double that accepted the initial LUT and rejected exactly one removal, two subsequent frames made no further removal attempt. Status correctly continued to report the old transform as applied. This demonstrates the retry behavior in the compositor. Physical display behavior still needs a native run. See [scene_bridge.c](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/scene_bridge.c#L1285) in `prepare_night_light` and `commit_frame`.

Give a rejected change one bounded retry on an otherwise conservative frame. Preserve the last applied transform and the rejection reason if the retry fails. When a direct-scanout frame and a LUT change fail together, the current branch handles the LUT first. Retry the pending change on a synchronized composed frame before attributing the rejection to the LUT. That branch ordering is source-verified. The headless test isolated only the transient LUT failure. Check enable, temperature change and disable against transient failure and persistent rejection. Verify that the output continues presenting in both cases and that it never enters a per-frame retry loop.

## Performance and unnecessary code

### Avoid projecting unaffected windows on floating resize

Every successful floating resize calls `Desktop::project`, which recomputes placement for every tracked view. The bridge updates content and borders even when that view's placement fields stayed the same. In a headless fixture with 96 mapped floating windows, 200 alternating one-pixel resize actions issued 19,200 placements. **19,000** had all placement fields identical to the previous call. The independent rerun recorded the same counts. At 8 and 32 windows, 1,400 of 1,600 and 6,200 of 6,400 placements were identical. See [desktop.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L235) in `project` and [scene_bridge.c](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/scene_bridge.c#L1906) in `seaside_scene_place_window`.

First compare a path that visits the resized floating window and its affected dialogs with a path that skips only demonstrably redundant placement work. Retain full projection on focus, stacking, output or tiled-layout changes. Compare fields by meaning. A raw `memcmp` can also compare struct padding. A surface commit, changed buffer, capture constraint or pending configure can need processing even when placement fields match. Use real clients to check all four. Measure full resize dispatch in the same optimized build, retaining resize/configure counts, input delivery, borders and captured output as correctness checks. Instrumented median CPU time per resize at 96 windows was 104.75 µs in the first review and 106.27 µs in the independent rerun. About 22 µs ran inside calls with identical placement. A proposed optimization still needs its own end-to-end measurement.

### Window lookup cost during desktop projection and window queries

`Desktop::project` places each tracked window by ID. `SessionControl::windows` also asks for each window's metadata by ID. Each call starts at the head of the same linked list in `find_view`. The lookup component alone grows quadratically with the number of live views. See [desktop.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L235), [session_control.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/session_control.cpp#L227) and [scene_bridge.c](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/scene_bridge.c#L190).

A disposable version of the existing headless desktop fixture mapped real xdg-toplevels, checked every returned app ID and counted linked-list nodes visited by a single metadata pass. For 8, 32, 64 and 128 windows the counts were **36, 528, 2,080 and 8,256**. These are operation counts. The gain in end-to-end query time or frame time still needs measurement.

Benchmark full projection and `query.windows` at those window counts in an optimized build. Compare a single batch traversal or a live ID index, retaining the list for scene ordering. Choose the smallest option that benefits the measured callers. Include destroy/remap, sparse IDs, hidden workspaces and stable query ordering. Accept a performance change after comparable runs show a lower full-operation cost without introducing work proportional to the highest ID ever issued.

### Drop resize work when logical geometry is unchanged

- **Subpixel motion.** The frame scheduler compares raw pointer coordinates, while resize movement truncates the delta to whole logical pixels. Four alternating subpixel changes scheduled four commits with the divider fixed at width 80. Suppress an idle resize frame when the effective delta is zero. Keep the latest pending target if the pointer reverses before dispatch, preserve fractional accumulation, and handle client-initiated edge resizing relative to its original anchor. Extend the stationary-pointer fixture to check all three paths. [Desktop motion and frame dispatch](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L850)
- **Floating size limits.** Five outward drag motions against a real client's maximum size produced five full projections with identical window geometry. A matching IPC action correctly succeeded with `changed=false`. Distinguish an eligible, constrained resize from an invalid target so the pointer path can skip projection while IPC keeps its existing result. Simply changing the window-manager return value would turn that accepted no-op into `invalid_state`. Cover both min/max hints and output-area limits. [Window resize](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/window_manager.cpp#L1475) · [Action dispatch](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L850)

### Profile the remaining IPC copies and idle polling

- **IPC publication.** Focus, workspace and output snapshots construct owning strings before comparing them. Short output IDs such as `out-1` can fit directly in a string object. The measured 33.48 µs at 64 workspaces in the previous handoff covers the entire unchanged publication. Its attribution to string allocations remains unproven. Measure allocations and complete publication time for short and long connector names, with and without subscribers. Compare borrowed names against the cache and copy only on a change if that improves the benchmark. Preserve initial events, ordering and lifetime across hotplug. [Snapshot construction](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/session_control.cpp#L205) · [Existing benchmark](../Parts/Part-10/HANDOFF.md)
- **Idle polling.** The ready session re-arms its observation timer for 100 ms, about ten wakeups per second. The tick checks output and input faults, hotplug, service recovery and child exits. An empty child list makes no `waitpid` calls. Power consumption and CPU sleep-state residency remain unmeasured. Profile idle wakeups first. Move individual duties to signals, callbacks or deadline timers only as equivalent coverage exists. Exercise VT return, hotplug, child cleanup and service restarts with the periodic fallback disabled before removing it. [Session timer and child reaping](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/session_entry.cpp#L1158)

### Use a single ordered collection of window IDs

`Desktop::views_` mirrors the ordered IDs in `DesktopState::windows()`. Its only readers are the desktop projection and the tiled-opening scan. Both use the state's window record inside the loop. A temporary build removed the set and its two mutation sites and ran both loops over the state map. All seven Part 4/5 tests passed, including headless mapping, opening, drag and destroy coverage. Make this a small standalone cleanup. Preserve the separate sets that track presentation and buffer fitting. See [desktop.hpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.hpp#L106), [desktop.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/desktop.cpp#L325) and [state.hpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/state.hpp#L76).

### Remove the duplicate trace-status object

Every production `query.diagnostics` builds a five-field empty trace object in `SessionControl::diagnostics`. Its only production caller immediately replaces that object with `Trace::status()`, which already describes all three states. Consolidate construction of the public response at the point that has the real trace state. Keep the output array and exact trace field types covered for empty, running and stopped traces. The current response is correct. This change removes duplicate schema maintenance. See [session_control.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/session_control.cpp#L331), [session_entry.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/session_entry.cpp#L634) and [trace.cpp](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/trace.cpp#L281).

### Limit file-descriptor wrapper consolidation to matching behavior

The config store and trace exporter have matching noncopyable wrappers with explicit checked close. IPC moves descriptors and the satellite manager also transfers and resets ownership. Share the matching pair first if touching both modules. Consolidate the others only if their move, release, reset and checked-close requirements survive intact and the change makes callers simpler. An all-at-once refactor has no demonstrated runtime gain. [Config storage](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/config_store.cpp#L18) · [Trace export](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/trace.cpp#L25) · [IPC](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/ipc.cpp#L32) · [Satellite process](https://github.com/Zelmari/seaside/blob/6777bd555ae2fc062b9609c2943e70d9ad1dd49e/src/satellite.cpp#L35)

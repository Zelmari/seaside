# Seaside desktop repair plan

Start with shutdown and immediate restart. A crash on exit can leave an owned portal running and block the next launch. The approved startup policy is to keep a usable Wayland session running when an external integration fails. The source baseline for these reports is `77c0607`.

## 1. Make shutdown and restart reliable

- During shutdown, `PortalActivation::stop()` dispatches the live loop after `Session::shut_down()` resets the trace. Queries still pass the trace by reference. Finish the exit acknowledgement, quiesce callbacks and IPC that depend on session objects, then retire those objects. Exercise diagnostics during delayed portal stops, pending trace exports, partial startup and repeated clean exits under ASan/UBSan. [Session teardown](../../src/session_entry.cpp) · [Portal cleanup](../../src/session_activation.cpp)
- Route SIGHUP through orderly termination. Handle SIGPIPE so a closed reader produces a write error and preserve normal signal handling in spawned programs. Test the real entry point with a closed reader and with HUP during startup and after readiness. [Server signals](../../src/server.cpp)
- Give the transient frontend, GTK and wlr portal units a systemd lifetime tied to their compositor instance, including abrupt process death. For leftovers from earlier builds, reclaim a unit only with evidence of its invocation and dead session. A name prefix or a reused PID is insufficient. Test immediate relaunch after a killed session, a concurrent live Seaside instance and a foreign portal owner. The latter two must keep their units and bus names. [Portal activation](../../src/session_activation.cpp)

## 2. Keep a usable session running through integration failures

- Make the desktop usable as soon as its Wayland server, seat and compositor are ready. Enable input, window management and local IPC, and run configured autostart once. Probe PipeWire, the user bus, systemd user services and portals asynchronously. Apply the same recovery policy to an outage present at login and one that begins later. An unrecoverable failure to initialize the compositor itself still returns control to the TTY. Preserve the supported zero-output session and VT switching. [Startup gate](../../src/startup_gate.cpp) · [Session readiness and recovery](../../src/session_entry.cpp)
- Show which feature is unavailable and why in `seasidectl status` and the session log. Use the existing integration failure and recovery events for transitions. Retry with deadlines and backoff, including when the bus connection or portal activation object could never be created. Verify the service works for this session before reporting recovery. When another desktop owns the portal, leave its units and activation environment alone and report Seaside's portal integration as unavailable.
- In the Arch guest, start with PipeWire unavailable, the user bus unreachable, and a portal name owned elsewhere in separate trials. Open a terminal, type, switch workspaces and inspect status. Restore each service, verify a new request succeeds in the same session and check that autostart ran once. Exercise a later outage, exit during retry, and a genuine core startup failure that returns to the original TTY. Update the preflight tests and startup guide alongside the implementation. [Startup IPC trial](../../tests/session/part6_vm_guest.py) · [Service recovery trial](../../tests/session/part9_vm_guest.py) · [Startup guide](../USER_GUIDE.md#start-and-exit)

## 3. Fix activation for applications and services

- The current launcher sets display variables on its children and transient portals. Other activated applications need the same session. After checking for a conflicting session and before starting units that pull in the graphical target, export `WAYLAND_DISPLAY`, `XDG_CURRENT_DESKTOP` and `XDG_SESSION_TYPE` to the Arch user manager and applicable D-Bus activation path. Publish `DISPLAY` and `XAUTHORITY` together when the satellite reservation succeeds. Prove that a freshly systemd-started client and a D-Bus-activated one each open a window on the intended display.
- Save prior manager values, including absence. On startup rollback and exit, restore only entries Seaside still owns, and exercise concurrent changes and crash/restart. Verify which activations the installed bus delegates to systemd. Classic D-Bus offers no unset operation. Use reversible or scoped activation where needed and document any residual limitation before claiming cross-login support. [Activation code](../../src/session_activation.cpp) · [D-Bus activation environment](https://dbus.freedesktop.org/doc/dbus-update-activation-environment.1.html)
- Watch the GTK backend alongside the frontend and wlr backend. Exercise loss and reacquisition of its verified owner through bounded recovery. Check that an existing Wayland client keeps accepting input and that a new GTK-backed portal request succeeds after recovery. [Portal watches](../../src/session_portal.cpp) · [Guest recovery trial](../../tests/session/part9_vm_guest.py)

## 4. Keep menus visible and keyboard focus consistent

- Test real panel menus with and without a grab. Layer popups inherit the parent's keyboard mode. An accepted XDG grab gives its topmost popup keyboard focus. Cover pointer-operated menus under `NONE`, keyboard grabs under `ON_DEMAND`, and clean dismissal of an incompatible grab. Check the tray client's requested mode and input serial before changing the compositor. [Layer-shell protocol](https://raw.githubusercontent.com/swaywm/wlr-protocols/master/unstable/wlr-layer-shell-unstable-v1.xml) · [XDG popup protocol](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/stable/xdg-shell/xdg-shell.xml)
- Make an active window's menu visible and hittable across a neighboring tile. Keep nested popups anchored and ordered through parent movement, clipping, workspace changes and fullscreen. When a shortcut, click or IPC action transfers focus during a grab, dismiss the affected grab in protocol order before routing keys to the new client. Verify pixels, pointer hits, key delivery and reported focus with two clients. [Scene stacking](../../src/scene_bridge.c) · [Layer popups](../../src/layer_scene.c) · [Focus actions](../../src/desktop.cpp)

## 5. Repair resizing, stacking and workspace behavior

- Give Dwindle keyboard resize a reversible split on each axis. Grow and shrink from either child and from a nested tile, checking size constraints and untouched siblings. During floating Super+right-drag, keep the latest resize target authoritative across delayed client commits and button release. Exercise delayed acknowledgements for both compositor-bound and client-requested resize. [Split resize](../../src/layout.cpp) · [Interactive resize](../../src/desktop.cpp)
- Raise the selected floating window through Alt+Tab while preserving cycle order. Keep floating and visible pinned windows reachable as new tiles map. Exercise overlapping windows, maximization, independent parent/dialog raises and fullscreen using both hit-tests and keyboard input. [Window stacking and focus](../../src/window_manager.cpp)
- A visible pinned window should participate in directional focus and Alt+Tab on its monitor. On unpin, propose keeping it on that monitor's displayed workspace, with focus, a single window identity and its appropriate tiled or floating state. Test switching away from the original workspace, changing the layout and moving a pinned window to another output.
- Exercise both workspace modes through startup configuration. Global mode selects a visible workspace in place and a hidden one on its last connected assignment. Per-monitor mode tracks an owner and reassigns it on explicit transfer. Both create new IDs on the focused monitor. Existing tests share many expectations. Trace hidden selection, temporary migration, manual transfer and reconnect to locate an observable ownership error before adding mode-specific branches. Verify reload reports a pending restart. [Workspace-mode tests](../../tests/unit/window_manager_test.cpp)

## 6. Correct monitor selection, pointer crossing and idle behavior

- For a requested refresh rate, prefer an exact advertised mode at the requested resolution, then the closest rate within a documented narrow tolerance. Report the applied mHz. Test 60, 144 and 165 Hz against 59951, 143998 and near-165000 mHz, plus explicit fractional rates, ties, unsupported modes and the existing automatic highest-refresh choice. [DRM mode selection](../../src/tty_drm.c)
- Test adjacent rotated and fractionally scaled outputs at the actual scene, IPC and pointer boundaries. Seaside's size calculation and the installed wlroots 0.20.2 effective-resolution helper both truncate. Change rounding only if the two-output test locates a mismatch. At the exposed edge of a taller monitor, propose keeping the pointer on that edge until it can cross at the same perpendicular coordinate. Preserve relative motion across aligned gaps and update the test that currently expects a vertical jump. [Output placement](../../src/output_config.cpp) · [Cursor tests](../../tests/unit/cursor_layout_test.cpp)
- Propose seat-wide input activity and wake for eligible displays. Today's tests explicitly expect independent wake. Exercise typing on A with B visible, waking two sleeping displays from one input, and a genuinely idle seat with fullscreen or an inhibitor on only one output. Keep the latter protections local to that output. [Idle policy](../../src/idle_power.cpp) · [Existing idle expectations](../../tests/unit/idle_power_test.cpp)

## 7. Preserve screen shares and recover frame presentation

- Distinguish DPMS sleep from removal of the capture source. Permit a sleeping monitor's stream to pause, release transient buffers, then resume the same source and portal session with a fresh frame on wake. Unplugging the monitor must terminate its source. Verify with a live PipeWire consumer across sleep, wake and unplug. [Monitor capture](../../src/output_capture.c)
- After a rejected tearing commit, fall back to synchronized presentation and limit further attempts until conditions change. Track every outstanding explicit-sync release point through repeated scanout rejection, replacement presentation and unplug. A client must regain its buffer once safe. Test for both premature reuse and a fence that never signals. Count failed and successful commits under sustained damage. [Frame commits](../../src/scene_bridge.c) · [Frame fault fixture](../../tests/integration/part8_frame_fault.c)
- Publish a completed selected-window frame when its GPU fence is ready. Remove the second 16 ms wait while retaining demand-driven pacing. Derive capture dimensions and sampling from source buffer scale, transform and viewport. Measure delivery timestamps with a 60 Hz producer, inspect a known HiDPI pixel pattern, and exercise resize, hidden workspaces and a stopped consumer. [Window capture](../../src/window_capture.c)

## 8. Complete clipboard, IPC and package compatibility

- Add wlroots data-control support for the installed external clipboard tools. Prefer `ext-data-control-v1` and include `wlr-data-control` where the tested clients require it. Define which clients may read or replace an unfocused seat selection and enforce that through the compositor's global filter. Verify `wl-copy`, `wl-paste --watch` with `cliphist`, primary selection and background X11 ↔ Wayland transfers in both directions. Clipboard storage stays with the external tool. [Clipboard trial](../../tests/session/part7_clipboard.py) · [wl-clipboard manual](https://raw.githubusercontent.com/bugaevc/wl-clipboard/master/data/wl-clipboard.1)
- Keep an `events.subscribe` connection open after the client calls `shutdown(SHUT_WR)`. The client should receive the acknowledgement and later events, including after a quiet period. Test full disconnect, ordinary request EOF, slow-reader limits and absence of an idle polling loop. [IPC peer handling](../../src/ipc.cpp)
- Relax the toml++ upper bound in both Meson and the PKGBUILD after checking parser behavior and linkage. Set `-Dwerror=false` for the package build, retain strict development checks, and let makepkg's debug settings govern split symbols. Build and install in a clean Arch environment, check package metadata and symbol files, then exercise an upgrade and config parsing. [Package recipe](../../packaging/PKGBUILD) · [Meson dependencies](../../meson.build)

## Verification order

For each fix, record a failing observation on the baseline and repeat it on the candidate. For a proposed policy change, record the old and new expected outcomes. Run the relevant fixtures and `tools/run-tests --suite unit --suite integration`, including a sanitizer build for lifecycle and buffer changes. Use the automated Arch guest runner for TTY relaunch, activation, menus, resize, clipboard, real portal streams and the installed package. Reserve physical AMD checks for tearing, explicit-sync buffer release, HiDPI cadence, real EDID modes and mixed-monitor DPMS/hotplug. [Test harness](../CONTRIBUTING.md#build-and-test) · [Native Arch checklist](NATIVE_ARCH_CHECKLIST.md)
